## 3. 弱点パターン分析

### 🔴 パターン1：部分文字列の誤マッチ（最重要）

**クエリ例**：「減給 制裁」→ 「**裁**判員等の休暇」が1位  
**原因**：文字単位トークナイズのため「制**裁**」の「裁」が「裁判員」にマッチ。  
**影響クエリ**：`減給 制裁`（×）

### 🔴 パターン2：条項番号の一意特定不能

**クエリ例**：「第30条」「第68条」→ 正しい規程の条文が出ない  
**原因**：複数規程に同番号が存在し、BM25は全文書を等しく探索するため、  
テキスト量が多い（または「第30条」の語が多く登場する）別規程が上位に来る。  
**影響クエリ**：`第30条`（×）、`第68条`（×）、`第15条`（△）

### 🟡 パターン3：概念の跨ぎマッチ（育児 vs 介護）

**クエリ例**：「介護休業 申請」→ 育児関連条文が1位  
**原因**：「育児・介護休業等に関する規程」は1つのファイルに両方含まれており、  
「休業」「申請」の共有トークンで育児条文が先にヒット。  
**影響クエリ**：`介護休業 申請`（×）、`育児休業 取得条件`（△）

### 🟡 パターン4：就業規則 vs 副次規程の優先度逆転

**クエリ例**：「懲戒処分 手続き」→ 健康情報取扱規程（副次規程）が1位  
**原因**：副次規程が就業規則より短くチャンク密度が高く、  
「懲戒」トークンが集中しているため、BM25スコアが高くなる。  
**影響クエリ**：`懲戒処分 手続き`（△）、`パワーハラスメント 定義`（△）

### 🟢 パターン5：スコア低下クエリ群

スコアが10以下のクエリは上位外れのリスクが高い。  
`所定労働時間`（8.9）、`試用期間 長さ`（15→2位以降は8点台）、  
`第15条`（4.6）は特に注意。

## 5. 改善策の優先順位

### 🥇 優先度：高

#### 改善1：条項番号検索へのファイルフィルタ必須化
- **対象バグ**：`第30条`（×）、`第68条`（×）
- **方法**：ユーザーが条文番号のみで検索する際、  
  `--filter-file 就業規則.pdf` をUIで促す、または  
  クエリに「就業規則 第30条」と規程名を含めるよう誘導する。
- **コスト**：低（UI/プロンプト変更のみ）

#### 改善2：形態素解析の導入（Janome/SudachiPy）
- **対象バグ**：`減給 制裁`（×）、部分文字列誤マッチ全般
- **方法**：文字単位 → 形態素単位トークナイズに変更。  
  「制裁」と「裁判員」を別トークンとして分離。
- **コスト**：中（`ingest.py` と `search_test.py` のトークナイザー変更）

```python
# 現在（文字単位）
tokens = list(query)

# 改善後（Janome例）
from janome.tokenizer import Tokenizer
t = Tokenizer()
tokens = [token.surface for token in t.tokenize(query)]
```

### 🥈 優先度：中

#### 改善3：同義語辞書の追加
- **対象バグ**：`減給 制裁` → `懲戒`、`自己都合退職` → `退職`
- **方法**：クエリ拡張（BM25検索前に同義語を展開）または  
  ingest時にメタデータとして同義語タグを付与。

| 元語 | 展開候補 |
|------|---------|
| 残業代 | 割増賃金 |
| 制裁 | 懲戒 |
| 辞表 | 退職届 |
| 有休 | 年次有給休暇 |

#### 改善4：ハイブリッド検索モードの活用推奨
- **対象バグ**：`育児休業 取得条件`（△）、`介護休業 申請`（×）
- **方法**：ベクトル検索（ChromaDB）との組み合わせにより  
  意味的類似度でカバーできる。`--mode hybrid` をデフォルト化。
- **コスト**：低（ChromaDB起動が前提）

---

### 🥉 優先度：低

#### 改善5：文書ランク重み付け（就業規則を優先）
- **対象バグ**：副次規程が就業規則より上位に来る問題
- **方法**：メタデータに `doc_priority`（就業規則=1.0、副次規程=0.8）を付与し、  
  BM25スコアに重み乗算。

#### 改善6：LLMによるクエリ展開（将来施策）
- **方法**：検索前にLLMで「介護休業 申請」→「介護休業 申出 手続き 申請書」に展開。  
  現在のバックエンドのチャットサービスと組み合わせやすい。

## 6. まとめ

現在のBM25システムは **Hit Rate@5 = 83%** と、単純キーワード検索としては  
十分な水準に達している。特に「残業代」「産前産後休業」「安全衛生委員会」のような  
**語彙が一致しやすいクエリでは非常に高精度**。

一方、次の3点が主要な弱点：

1. **文字単位トークナイズの誤マッチ**（制裁→裁判員）→ 形態素解析で解決可能
2. **条項番号検索の精度低さ**（33%）→ ファイルフィルタUIで即改善
3. **概念跨ぎ問題**（育児 vs 介護）→ ハイブリッド検索 or クエリ展開

**最短の改善パス**：  
`条項番号フィルタUI` → `形態素解析導入` → `ハイブリッドモードのデフォルト化`

この順で実施することで、Hit Rate@5は **83% → 推定91%以上**に改善できる見込み。
