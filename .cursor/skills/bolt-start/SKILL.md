# 新しいボルトを開始する

## STEP 0: ボルトが必要か判断する
bolt-workflow.mdc の「ボルト不要のケース」に該当する場合（typo修正、設定変更、ドキュメントのみの更新、調査・PoCなど）、ボルトを作成せず直接作業してよい旨をユーザーに伝える。判断に迷う場合はユーザーに確認する。

## STEP 1: ボルト番号の採番
`docs/aidlc/bolts/` を確認し、現在の最大番号の次を採番する。フォルダが存在しない場合は `bolt-001` から開始。

## STEP 2: Intentのヒアリング
以下をユーザーに質問する：
1. このボルトで達成したいことは何か？（1〜2文で）
2. 完了したとみなせる条件は何か？
3. 影響を受けるファイル・テーブルの見当はあるか？

## STEP 3: タスク分解の提案（会話の反転）
ヒアリング内容をもとに以下を提示し、承認を得る：
- `[SQL]` `[PHP]` `[VIEW]` `[TEST]` `[DOC]` `[CONFIG]` カテゴリ別タスク一覧
- 実装の推奨順序
- ブランチ名の案（`bolt/bolt-NNN-<slug>`）

承認を得るまで実装しない。

## STEP 4: ドキュメント作成
承認後、以下3ファイルを作成する。

### intent.md テンプレート
```markdown
# bolt-NNN: <タイトル>

## Intent（目的）
<何を達成するか1〜2文>

## 完了条件
- [ ] <条件1>
- [ ] <条件2>

## 対象範囲
- 対象テーブル: 
- 対象ファイル: 
- 対象画面: 
```

### tasks.md テンプレート
```markdown
# bolt-NNN タスク一覧

## [SQL] データベース
- [ ] <テーブル変更・追加など（なければ削除）>

## [PHP] ロジック
- [ ] <Entity/Repository/Service/Action の変更>

## [VIEW] 画面
- [ ] <public/ 配下の変更>

## [TEST] テスト
- [ ] <PHPUnit テストの追加・修正>

## [DOC] ドキュメント
- [ ] <docs/ 配下の変更（なければ削除）>

## [CONFIG] 設定
- [ ] <設定ファイル・CI/CD 等の変更（なければ削除）>
```

### progress.md テンプレート
```markdown
# bolt-NNN 進捗

## ステータス
🔴 未着手

## 参照スキル・ルール
<!-- 作業中に参照したスキルファイルやルールファイルをここに記録する -->
- YYYY-MM-DD: `.cursor/skills/bolt-start/SKILL.md` を参照（ボルト開始）

## 作業ログ
- YYYY-MM-DD: ボルト開始
```

## STEP 5: ブランチ作成を提案
以下コマンドを提案し、ユーザーに実行を促す：
```bash
git checkout -b bolt/bolt-NNN-<slug>
```
